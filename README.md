# ArthroHarm

ArthroHarm is a deterministic research prototype for identifying and structuring harms evidence from full-text reports of randomized trials in total knee arthroplasty (TKA/TKR).

Repository: <https://github.com/RuiZhang-doc/ArthroHarm>

## Scope and intended use

This release contains the exact ArthroHarm v1.2 extractor, rules, publisher adapters and automatic evaluation code used in the reported Stage II evaluation, together with synthetic tests and governance utilities. It is intended for methods research, reproducibility checks and human-in-the-loop evidence-synthesis workflows.

ArthroHarm is **not** a clinical decision-support system, medical device, autonomous systematic-review system or substitute for dual human review. In the locked primary Stage II external validation, the automatic matcher achieved 65.96% precision, 28.01% recall and an F1 score of 39.32% at the reference-harms-evidence-unit level. The low recall precludes autonomous use.

## Release contents

- `arthroharm_extract_v1_2.py`: frozen v1.2 extraction logic.
- `arthroharm_extract_v1_1.py`: imported frozen base required by v1.2.
- `arthroharm_rules_v1.0.json`, `arthroharm_rules_v1.1.json`, `arthroharm_rules_v1.2.json`: versioned rule lineage.
- `normalize_publisher_fulltext_v1_2.py`: label-free HTML-to-minimal-JATS adapter.
- `normalize_publisher_pdf_v1_2.py`: label-free coordinate-aware PDF-to-minimal-JATS adapter.
- `arthroharm_evaluation_v1_2.py`: frozen automatic matcher, field scoring and report-cluster bootstrap.
- `run_stage2_external_scoring_v1_2.py`: audited one-time scoring wrapper.
- capsule freeze, prediction-seal and reproducibility-verification utilities.
- 37 synthetic unit/regression tests and one runnable synthetic example.
- cryptographic manifests describing the evaluated and public-release artifacts.

## Requirements

- Python 3.10 or later.
- `lxml` and `pdfplumber` for the publisher adapters.
- Poppler `pdftotext` for the PDF adapter command-line workflow.

Install Python dependencies in an isolated environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Install Poppler separately when the PDF adapter is required (for example, `brew install poppler` on macOS or `apt-get install poppler-utils` on Debian/Ubuntu).

## Run the tests

```bash
python -m unittest -v \
  test_arthroharm_v1_1.py \
  test_arthroharm_v1_2.py \
  test_arthroharm_evaluation_v1_2.py \
  test_normalize_publisher_fulltext_v1_2.py \
  test_normalize_publisher_pdf_v1_2.py
```

## Run the synthetic example

```bash
python arthroharm_extract_v1_2.py \
  --input-dir examples/synthetic_input \
  --rules arthroharm_rules_v1.2.json \
  --output-dir examples/synthetic_output_rerun \
  --run-mode development
```

The expected outputs in `examples/synthetic_output/` were generated by the released extractor. Compare files with `sha256sum` or `shasum -a 256` after normalizing only platform-dependent path metadata, if present.

## Input and output boundary

The extractor expects JATS or minimal-JATS-like XML/NXML. Publisher HTML and PDF inputs must first be normalized with the provided label-free adapters. Source reports must be obtained lawfully by the user. The repository does not redistribute publisher full texts, figures, tables or substantial verbatim passages.

See [DATA_AND_COPYRIGHT.md](docs/DATA_AND_COPYRIGHT.md) and [SOFTWARE_PROVENANCE.md](docs/SOFTWARE_PROVENANCE.md) for the release boundary and exact evaluated-file hashes.

## Reproducibility limits

The public code and synthetic fixtures are sufficient to inspect and test the algorithms. Exact end-to-end rerunning of the published corpus additionally requires lawful access to the same source-report versions. Rights-cleared derived evaluation tables will be released with the manuscript supplements; publisher full texts will not be redistributed.
